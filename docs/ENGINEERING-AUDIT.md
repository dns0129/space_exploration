# 工程审查与轻量化记录

审查日期：2026-10-12。比较基线：`f7b4e72`。

## 判断

项目的生产依赖只有 Three.js 与 Rapier；后端只使用 Node.js 内置模块。审查时通过 Vite 的首页与游戏双入口实际依赖图检查，`src/` 的 48 个 TypeScript/CSS 文件全部可达，没有发现可以直接删除的大块废弃业务模块。当前主要成本来自高清素材、嵌入式地形数据、物理引擎和渲染循环。轻量化应优先减少重复计算、对象分配和非必要资源发布。

上次统计的 29,082 行包含 9,953 行测试。测试、历史下载包、素材制作脚本及许可记录不属于浏览器运行负担；清理它们无法改善游戏帧率。高度场虽只有少量物理行，却包含约 6.39 MB 文本数据，因此代码行数不能衡量下载与运行成本。

## 当前结构

| 层次 | 主要入口 | 职责与评价 |
| --- | --- | --- |
| 页面和界面 | `src/main.ts`、`flight-ui.ts`、`panel-layout.ts`、`site.ts` | 首页没有第二个 WebGL 场景；控制、存档与布局已有独立模块。 |

| 视觉模块 | 星球、天空、地表、飞船与星舰模型 | 已有 LOD、纹理按需加载、局部场景与静止帧复用；这些机制仍在使用。 |
| 后端 | `server/server.mjs` | 约 200 行，提供静态资源与会话存档，依赖已很轻。 |
| 制作与交付 | `scripts/`、Actions | 同一源码输出网站、单文件 HTML 和包含后端的 ZIP；素材制作脚本保留可追溯性。 |

## 本次实际修改

| 修改 | 判定依据 | 收益 |
| --- | --- | --- |
| 删除 `nav-planned`、`mobile-open`、`flight-nav-note` 的 24 行样式 | 页面模板、事件逻辑及动态类名中均没有对应使用 | 减少旧界面遗留样式。动态生成的 `ui-dock-*` 等有效样式保留。 |
| 删除地表未使用导入及 3 个未读取的 uniform | `groundVisibility`、`groundExtent`、`groundHorizonOffset` 没有 GLSL 读取点 | 减少无效状态及每帧无效赋值。 |
| 删除退役轨道引擎空方法、固定返回值及 HUD 字段 | 当前界面与快捷键没有消费者；空接口只有自身回归断言 | 移除 5 行空接口和 4 行无效 HUD 契约；删除只验证空方法的旧测试。旧存档迁移、有效的五档推进测试继续保留。 |
| 删除环境查询的 6 个遗留字段，单次查询只筛选一次天体 | `nearHeightKm`、`headingOut`、`movingOut`、`escaping`、`orbitalRequired`、`restricted` 均没有消费者 | 每次查询少创建一个向量和一份天体数组，减少无效姿态运算和输出字段；有效的低空、地形、大气状态继续保留。 |
| 删除资源清理中的重复场景遍历 | 同一 `surfaceWorldScene` 被遍历两次，资源本来已用 Set 去重 | 退出场景时减少重复工作。 |
| 地表网格每个顶点只采样一次高度，复用向量、颜色与输入数组 | 原先先调用 `terrainHeightKm`，随后 `sampleSurface` 再算同一高度；循环还不断创建比例转换器和临时对象 | 减少地表进入和网格重建的 CPU 峰值及垃圾回收压力。 |
| 直接写入地表与碰撞网格的 Float32 数组 | 原先先构建普通数组或逐顶点生成临时数组，再复制 | 减少分配和数据复制，保留原来的网格尺寸与精度。 |
| 徒步相机复用计算对象 | 原先每帧 clone/new 多个向量、四元数及矩阵 | 减少徒步时短生命周期对象；碰撞仍由原来的 Rapier 查询处理。 |
| 星舰材质在创建时收集 | 静态舰体原先在可绘制帧中重复遍历全部节点 | 当前舰体已合并为 7 个标准材质网格；每帧从遍历 10 个节点改为直接更新 7 个材质。此项收益较小，主要减少递归与回调工作。 |
| 网站发布排除两张退役图片 | atlas 已退出游戏材质；旧半人马座天空只作素材档案，当前背景使用银河照片 | 网站产物减少 736,383 字节（约 0.70 MiB）。Git 内原图、来源记录和历史包保留。在线仍使用的 8K 地球高程图继续发布。 |
| 开启 `noUnusedLocals` 和 `noUnusedParameters` | 清理后源码可通过这两项检查 | 将 TypeScript 未使用项检查纳入所有现有构建，减少再次积累。 |

## 测得的局部收益

使用 Node.js 24 对基线和修改版的同一地表构建方法进行交替采样：每个版本预热 3 次，再采样 9 次，取中位数。球面包含 31,073 个顶点。五种天体的全部 position、normal、surfaceRadial 与 color 属性逐元素比较，差异均为零。

| 天体 | 修改前 | 修改后 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 地球 | 310.7 ms | 180.8 ms | 41.8% |
| 月球 | 236.3 ms | 147.5 ms | 37.6% |
| 火星 | 195.4 ms | 106.4 ms | 45.6% |
| 塔拉萨 | 95.0 ms | 65.0 ms | 31.6% |
| 巴纳德星 b | 269.5 ms | 204.7 ms | 24.1% |

这是该云机器上的 CPU 网格重建数据，期间还有浏览器验证负载，适合说明局部变化与数据一致性，不是显卡帧率成绩。持续运行的 FPS 还受 GPU、着色器、窗口尺寸、纹理上传及自适应分辨率影响；不能将上述百分比直接换算成整机帧率提升。

另外对全部 45 个使用完整地表球面的天体做了同一位置的属性比较：顶点、法线和径向属性全部完全一致，41 个天体的颜色也完全一致；其余 4 个的最大颜色差为 `4.77e-7`，来自高度换算的浮点舍入，远低于 8 位颜色的一个灰阶。证据位于 `test-results/engineering/surface-equivalence.json`。

## 后续建议，按预期收益排序

1. **将地形数据与物理引擎按使用场景加载。** 基线生产游戏入口约 9.31 MB（gzip 约 4.48 MB），其中源高度数据约 6.39 MB，Rapier 分发模块约 2.24 MB。可先分离地形数据，再把 Rapier 加载与初始化延迟到首次徒步。当前高度查询和徒步入口为同步契约，在线、离线和后端必须一起设计加载与回退，不能直接删除或只加一个动态 import。
2. **从 `SolarScene` 提取贴图资源管理器和渲染模式协调器。** 该类同时承担加载、LRU、上传、相机、模式切换和释放。先保持现有公开控制接口与存档格式，将资源生命周期独立，再拆相机或场景。文件拆分改善维护性；需要配合按需实例化/加载才会降低运行成本。发布前整合的主分支更新已将静止帧复用扩展到观测与太空模式；拆分时应保留相机、纹理、材质淡入和摄影操作的画面失效机制。
3. **减少一帧内重复的环境查询。** `ShipDynamics.environment` 会扫描当前天体并采样地表；多个光照、相机、天空和 HUD 路径会重复取值。单次查询的死字段和重复筛选已清理；后续可在物理步结束后创建一份帧内快照，传给只读消费者。需要覆盖跃迁、星舰移动、重定位和恢复；不应使用跨帧缓存，否则可能引入一帧滞后的碰撞或光照。
4. **按首次进入模式创建本地人物与登陆艇。** 当前观测页也会创建徒步视图和另一套飞船资源。适合在资源管理边界清楚后延迟实例化，验证首次离舱、摄影与资源释放。
5. **整理 CSS 的布局所有权与资源清单。** `style.css` 约 2,500 行，`site.css` 约 1,300 行，新面板样式会覆盖一些旧布局规则。应按观测、航行和面板逐组比较实际布局后删除覆盖规则。素材源档案、网站发布资源与离线资源也可统一从一份清单派生，避免漏删有效资源。

以下内容本次保留：Three.js、Rapier、43 个原有球形天体及新增航区、旧存档校验与迁移、高清/低内存回退、共享地形与浮动原点、模型 LOD、自适应分辨率、静止帧复用、历史 ZIP 和许可证。它们有实际功能或交付用途。
